## Event argument types

OccupierAddedEventArgs<T> and OccupierRemovedEventArgs<T> derive from EventArgs. Each exposes public readonly Cell:int, Location:Point, and Occupier:T. Each has constructors taking (CellMetrics,int,T) or (CellMetrics,Point,T); the constructor stores the supplied coordinate and derives the other through GetLocation/GetCell without checking the returned bool.

## OccupierSet<T> state

Generic constraints: T : class, ICellOccupier. Implements IEnumerable<(Point Location,T Occupier)> and non-generic IEnumerable.

- metrics: private readonly CellMetrics.
- occupiers: private readonly Dictionary<T,Point>, mapping each object to its anchor/origin.
- occupierCells: private readonly T[,], a per-cell lookup array sized [metrics.Height, metrics.Width].
- Indexers: Point delegates to x/y; x/y returns null out of bounds; flattened cell resolves through metrics.GetLocation; object indexer returns nullable anchor Point.
- Occupiers exposes dictionary keys as IEnumerable<T>.
- Events: OccupierAdded, OccupierRemoved, Cleared.

## Public API and body behavior

- Constructor stores metrics and allocates the occupancy array.
- CanAdd overloads accept Point, x/y, or flattened cell, optionally an explicit bool[,] mask. Null objects and already-registered objects are rejected. The default-mask overloads use occupier.OccupyMask. The mask overload materializes GetOccupyPoints and rejects if any mask point is out of bounds or already occupied.
- Add overloads mirror CanAdd. Add calls DoAdd; on success it raises OccupierAdded after both dictionary and array state have been written.
- Clear empties the dictionary, clears the entire array, then raises one Cleared event. It does not emit individual OccupierRemoved events.
- Contains overloads test grid coordinates, flattened IDs, or dictionary membership.
- GetEnumerator projects each dictionary entry to (anchor location, occupier); dictionary iteration order is not explicitly sorted.
- Remove(T) captures the old anchor, calls DoRemove, then raises OccupierRemoved only on success. Remove(Point) resolves the current cell's occupant and delegates; x/y and flattened overloads delegate through the same path.
- OfType<U>() filters enumeration by runtime type and casts matching occupiers.
- OnOccupierAdded, OnOccupierRemoved, and OnCleared are protected virtual event dispatchers.
- DoAdd rejects null/duplicate objects, materializes all mask points, rejects if any point is out of bounds or occupied, then stores the anchor and writes the object into each mask cell.
- GetOccupyPoints(Point,bool[,]) walks mask rows then columns and yields origin + (x,y) for each true element. The mask therefore describes non-negative offsets from the anchor.
- DoRemove rejects null/unregistered objects, removes the dictionary entry, then scans from the anchor's Y/X through the bottom/right of the entire array and clears cells whose value equals the removed occupier. This scan direction is sufficient for masks generated by GetOccupyPoints because they only extend down/right from the anchor.

## Contracts and edge cases

CanAdd and Add share the same bounds/conflict test. Add mutates before raising the event. A zero-sized/all-false mask can register an occupier in the dictionary while occupying no cells. A null mask fails when GetLength is accessed. Clear has a distinct event contract from repeated Remove. Remove(Point) on an empty cell delegates null and returns false. The grid supports only positive mask offsets; it cannot represent an occupancy footprint extending above/left of its anchor.

Building and Terrain types supply masks through ICellOccupier. BuildingType distinguishes BaseOccupyMask from OccupyMask; the Map model registers a Building in the Buildings set using the full BuildingSet mask, then registers it in Technos with BaseOccupyMask and manages bib smudges separately.

## Rust comparison

No occupancy collection, per-cell owner index, arbitrary mask placement, or add/remove/clear event stream exists in the current crates/map-editor-model. CellLayers is not a substitute for this multi-cell object occupancy index. A Rust implementation should use a stable object ID or arena handle, validate the full mask before mutation, and define event/command behavior separately from storage.
